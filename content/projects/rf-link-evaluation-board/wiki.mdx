## Project Purpose

The RF Telemetry System is the vehicle-side communications subsystem responsible for moving flight data from the onboard computing stack to the ground station while also reporting whether the radio link itself is healthy.

The project grew out of a practical failure mode: flight data is only useful if it can be recovered. The current LR2021-based revision therefore treats telemetry as more than a radio. It combines data transport, RF amplification and filtering, antenna selection, forward/reflected power sensing, electrical and thermal monitoring, and hardware fault handling.

The public portfolio page intentionally separates three classes of information: architecture decisions, preliminary design targets, and measured results. Anything not yet validated on hardware is presented as a target or open item rather than as a finished specification.

## System Requirements

| ID | Requirement | Current approach |
| --- | --- | --- |
| RF-001 | Support long-range vehicle telemetry | 915 MHz LR2021 path |
| RF-002 | Support a higher-rate short-range mode | 2.4 GHz LR2021 path |
| RF-003 | Deliver approximately 1 W RF output per active band | External PA chain; final conducted/antenna power pending validation |
| RF-004 | Share antennas between TX and RX without wasting several dB in a passive split | Switched half-duplex T/R architecture |
| RF-005 | Provide antenna/path diversity | RF switch network controlled by the telemetry supervisor |
| RF-006 | Observe forward and reflected transmit power | Directional coupler + logarithmic detector + ADC telemetry |
| RF-007 | Prevent unsafe PA/LNA states | Hardware gating plus software sequencing |
| RF-008 | Protect critical RF loads from thermal/electrical faults | Comparator/eFuse shutdown paths plus monitored telemetry |
| RF-009 | Keep flight-data transport separate from low-level radio control | Flight computer → Ethernet → CM5 → SPI → LR2021 |
| RF-010 | Preserve evidence for post-flight diagnosis | Fault, current, voltage, temperature, and RF-health logging |

## High-Level Architecture

| Subsystem | Responsibility |
| --- | --- |
| Flight computer | Produces vehicle telemetry and sends packets over Ethernet |
| CM5 telemetry supervisor | Buffers/prioritizes data, configures the LR2021, sequences RF states, reads health telemetry, and records faults |
| LR2021 | LoRa/modem and RF transceiver for the 915 MHz and 2.4 GHz operating modes |
| RF front end | PA/LNA gain, band filtering, T/R switching, antenna selection, and high-power RF routing |
| Measurement chain | Forward/reflected RF power, temperature, current, and voltage telemetry |
| Hardware protection | Independent shutdown of unsafe RF states without relying only on Linux software |

## Operating Strategy

The radio is operated half-duplex with one RF band active at a time. The intended mission strategy is to favor 915 MHz when link margin is the priority, then use 2.4 GHz when the link is strong enough to justify the higher-rate mode.

| Mode | LR2021 state | 915 PA | 915 LNA | 2.4 PA | 2.4 LNA |
| --- | --- | --- | --- | --- | --- |
| RX 915 | Receive | Off | On | Off | Off |
| TX 915 | Transmit | On | Off | Off | Off |
| RX 2.4 | Receive | Off | Off | Off | On |
| TX 2.4 | Transmit | Off | Off | On | Off |
| Fault / safe | Standby or disabled | Off | Off | Off | Off |

<DesignDecision title="RF switches are never treated as hot-switch devices">
Before a T/R or antenna-selection change, the active PA and LNA are disabled. The system allows RF energy to decay, changes the switch state, waits for the switch to settle, and then enables only the amplifier required for the new mode. Hardware logic is intended to prevent software from commanding a known-unsafe combination.
</DesignDecision>

## RF Signal Chains

The transmit chain for each band follows the same functional pattern:

| TX stage | Function |
| --- | --- |
| LR2021 RF output | Generates the commanded LoRa waveform |
| Power amplifier | Raises the transceiver output toward the approximately 1 W system target |
| Low-pass filter | Suppresses PA-generated harmonics before the antenna path |
| Directional coupler | Samples forward and reflected traveling waves with low main-line loss |
| RF switch network | Selects T/R state and antenna path |
| Antenna | Radiates the selected 915 MHz or 2.4 GHz signal |

The receive chain reverses the emphasis: antenna selection is followed by low-noise gain and band-selective filtering before the LR2021 input.

| RX stage | Function |
| --- | --- |
| Antenna + diversity switch | Selects the available receive path |
| T/R switch | Routes the antenna toward the receive chain |
| LNA | Raises weak received signals while minimizing added noise |
| Band-pass filtering | Rejects out-of-band energy before the transceiver |
| LR2021 RF input | Demodulates the selected band |

## RF Health and Fault Awareness

The design treats observability as part of the RF architecture rather than as an afterthought. Forward and reflected power help distinguish a transmitter problem from an antenna/path mismatch. Current and voltage telemetry help identify power-tree faults, while temperature sensing gives both software and hardware a view of thermal stress.

The important distinction is between telemetry and protection. The CM5 may reduce power, change antennas, or log a warning, but critical faults also have a path that can remove RF enable or power without waiting for Linux software.

## Design Decisions

| Decision | Selected approach | Why |
| --- | --- | --- |
| TX/RX sharing | RF T/R switches | Low insertion loss and compatible with the half-duplex radio |
| Passive Wilkinson as primary T/R element | Rejected | A simple split spends valuable transmit power continuously |
| Circulator | Not selected | Size, cost, insertion loss, and integration penalties |
| Duplexer for simultaneous operation | Not selected | The design does not require simultaneous TX/RX and isolation becomes difficult around a high-power PA |
| RF link health | Coupler + detector telemetry | Provides evidence that RF energy actually reached the antenna path |
| Protection ownership | Hardware + software | Software supervises behavior; hardware retains authority to force unsafe RF states off |

## Current Design Status

The architecture and schematic are still being refined. The following items should remain explicit until measured or finalized:

- Final LR2021 drive settings for each external PA
- Conducted output power and downstream switch/filter loss
- Final LNA and filter selections for each band
- Directional-coupler and detector calibration constants
- Thermal shutdown thresholds and latch/recovery behavior
- Final board stackup and controlled-impedance geometry
- Antenna-switch insertion loss and isolation
- Full link-budget assumptions and ground-station configuration
- Measured RF spectral performance, VSWR accuracy, and thermal performance
